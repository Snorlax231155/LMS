Project: Library Management System (LMS)

Overview
--------
The Library Management System (LMS) is an ASP.NET Core web application (Razor MVC controllers + views) built on .NET 10.0. It provides functionality to manage books, borrow/return records, students, librarians, and simple authentication.

Repository layout
-----------------
- /LMS/           -> ASP.NET Core web project (main application)
  - Controllers/  -> MVC controllers (BooksController, BorrowController, HomeController, DashboardController, MagazineController, NewspaperController, etc.)
  - Models/       -> Domain models (Book, BorrowRecord, StudentModel, LibrarianModel, LoginModel, Magazine, Newspaper, DashboardModel)
  - Views/        -> Razor views for the controllers and shared layout
  - Migrations/   -> EF Core migrations (generated)
  - appsettings.json -> Configuration (DefaultConnection string for LocalDB)
  - Program.cs    -> App startup, service registration and auto-migration logic
  - LMS.csproj    -> project file and package references
- /TestProject1/  -> xUnit test project containing controller unit tests using FluentAssertions and EF InMemory provider
- CAPSTONE_DOCUMENTATION.txt -> This file

Technology stack
----------------
- .NET 10 (TargetFramework: net10.0)
- ASP.NET Core MVC (Razor Views)
- Entity Framework Core (SqlServer provider for runtime, InMemory provider for unit tests)
- SQL Server LocalDB for development database (connection string in appsettings.json)
- xUnit + FluentAssertions for unit tests

Key Features
------------
- Book CRUD (Create, Read, Update, Delete)
- Borrow/Return flow (BorrowController) with BorrowRecord tracking
- Dashboard showing totals (books, students, currently borrowed)
- Seeded sample data via EF Core HasData and migrations
- Search and pagination (Books Index: 5 books per page)
- Separate sections for Magazines and Newspapers (in-memory examples)
- About and Contact pages
- Automated development convenience: Program.cs attempts to scaffold migrations (development-only) and run migrations at startup

Important Files and Purpose
--------------------------
- Program.cs: Registers services, configures EF Core, and runs auto-migration logic in Development.
- appsettings.json: DefaultConnection uses (localdb)\\MSSQLLocalDB;Initial Catalog=LMS
- Models/Book.cs: Book entity with validation attributes
- Models/BorrowRecord.cs: Borrow record entity with BorrowDate and ReturnDate
- Models/LibraryContext.cs: DbContext with DbSet<Book>, DbSet<BorrowRecord>, Students, Librarians, and LoginTab. Seeds data in OnModelCreating.
- Controllers/BooksController.cs: Book list, details, create, edit, delete. Index supports searchString and page parameters for pagination.
- Controllers/BorrowController.cs: Create and Return actions for borrowing flow; includes new Borrow/Index selection listing.
- Views/Books/Index.cshtml: Search bar, Add button, table, and pagination UI
- Views/Shared/_Layout.cshtml: Main layout and navigation updated with Borrow, Magazine, Newspaper, Dashboard, About, Contact links
- Migrations/: Contains EF Core migrations. After running migrations database will be created with tables and seeded data.
- TestProject1/: xUnit tests for BooksController using EF InMemory provider and FluentAssertions

Setup and Local Development
---------------------------
Prerequisites:
- .NET 10 SDK
- SQL Server LocalDB (installed with Visual Studio) or another SQL Server instance
- (Optional) dotnet-ef tool: `dotnet tool install --global dotnet-ef`
- (Optional) Git and GitHub CLI (gh) for repository operations

Local run steps:
1. Open solution in Visual Studio or use CLI.
2. Ensure connection string in LMS/appsettings.json points to your SQL Server instance. For LocalDB default: `Data Source=(localdb)\\MSSQLLocalDB;Initial Catalog=LMS;...`
3. If this is the first run:
   - Either run migrations manually:
	 - `dotnet ef migrations add InitialCreate -p LMS -s LMS` (if needed)
	 - `dotnet ef database update -p LMS -s LMS`
   - Or start the app (in Development) and Program.cs will attempt to scaffold and apply migrations automatically. Note: automatic scaffolding uses dotnet-ef and requires the CLI and permissions.
4. Run the app (Visual Studio F5 or `dotnet run --project LMS`).
5. Browse to http://localhost:5000 (or the configured URL). The home page shows featured books and stats.

Running tests
-------------
From repo root, run:
- `dotnet test TestProject1/TestProject1.csproj` or run tests from Visual Studio Test Explorer.

Testing strategy
----------------
- Controller unit tests use EF Core InMemory provider to avoid touching real DB.
- FluentAssertions used for expressive assertions.
- Tests cover pagination, search filtering, and details actions for BooksController.

EF Core and Migrations
----------------------
- LibraryContext seeds initial data via `OnModelCreating` using `HasData`.
- Migrations generated are stored under LMS/Migrations.
- Program.cs contains helper logic (development-only) to scaffold a migration automatically if no migrations exist and to apply migrations on startup.
- For production, manual EF migration management is recommended.

Security and secrets
--------------------
- Connection strings are stored in appsettings.json for development. Move to secure storage (user secrets, environment variables, Key Vault) for production.
- Do not commit production credentials into the repository.

CI / CD and Deployment
----------------------
- Build and test in CI using `dotnet build` and `dotnet test`.
- For deployment, configure environment variables and a production-grade database connection.
- Remove or disable runtime-scaffolding of migrations in Program.cs for production.

Recommended Enhancements
------------------------
- Add authentication and role-based authorization (librarian vs. student).
- Persist magazines and newspapers into the database.
- Improve search to be case-insensitive and add sort options.
- Implement paging links component and client-side enhancements.
- Add integration tests (end-to-end) using WebApplicationFactory and TestServer.

Troubleshooting
---------------
- If migrations fail due to existing tables, drop the database (dev only) with `dotnet ef database drop -p LMS -s LMS -f` then `dotnet ef database update`.
- If `dotnet ef` commands are not found, install dotnet-ef:
  - `dotnet tool install --global dotnet-ef`
